CRISP Go Port — Validation Journey

Byte-parity validation of the Go critical-path analyzer against the Python reference · September 2026
TL;DR. The Go port of CRISP's light/conformance pipeline is byte-identical to the Python reference on all 1,559,520 traces across two public Zenodo datasets (the artifact corpus and the 1.39M-trace Tale of Errors corpus) — fully reproducible by anyone. Along the way we fixed a real semantic divergence (multi-root skip behavior), made a pathological 120k-span trace 277× faster via a semantics-preserving algorithmic fix, verified ~1M-span traces complete in 13s / 2GB RAM, and measured wall-clock wins from 48–89× on small traces (interpreter-startup elimination) to a 1.6× analysis-time speedup on the corpus' 119,680-span largest trace.

How we did it

1
Staged port behind a difftest harness. The Go port landed as a reviewed PR chain — #62 bootstrap (Jaeger decoding, span classification, difftest harness), #63 trace-merge, #64 graph construction, #65 critical path, #66 outputs, #67 CLI — each gated on 33 golden fixtures. The harness' corpus mode (-strict) byte-compares all six light-mode outputs per trace: conformance.cct/json, light-flame-graph-P100.{cct,dot,pb}, slackDrag.csv (row-sorted, absorbing pandas' unstable-quicksort tie order). A sha256-keyed reference cache makes refresh resume-safe — interruptible and transferable between machines.
2
Zenodo corpora: 1.56M traces, one real divergence found. Ran strict byte-comparison on two public datasets on a 96-core box (64 workers + per-process BLAS thread caps, leaving headroom for concurrent download work): the research artifact (bottom-up-trace 100k, Service43-Operation159 50k, ml-service3 21k) and the Tale of Errors in Microservices corpus, both artifact parts (trace1 + trace2, 1,388,527 traces). The first corpus immediately surfaced a porting bug: Python skips traces with no root or multiple roots (log warning, rootNode=None), while the Go port returned a hard error and aborted. Fixed to skip-identically (434e09c), after which 170,993/170,993 and 1,388,527/1,388,527 passed byte-identical — including skip-for-skip agreement and a 119,680-span monster trace (17m05s Python / 10m37s Go).
3
Preparing for 1M-span traces (Jaeger guidance). Profiling the 120k-span trace showed ~87% of time in sorting: CalculateDrag re-sorted a parent's entire children slice for every critical-path node sharing that parent — O(|cp| × fanout log fanout), faithfully matching Python's per-node sorted(). Memoizing the order per parent is semantics-preserving (stable-sort-then-reverse is deterministic), giving byte-identical output at 277× speed (10m37s → 2.3s). A synthetic 957,441-span single-root trace then completed in 13s at 2.0GB RSS — slow-but-safe as required, actually quite fast. The Go library spawns zero goroutines and has no mutable globals, so library callers own the parallelism budget entirely (no numpy/BLAS-style hidden thread pools like Python).
4
Invocation-mode benchmark (fully reproducible). A random 100-trace sample (seed 42) of the public bottom-up-trace dataset, 8 workers, BLAS threads capped, three deployment shapes timed end-to-end. Outputs verified A == B == C byte-identical on every trace. One operational lesson fell out: real traces are rarely single-rooted (orphan spans from sampling/truncation), and --rootTrace skips such traces by design — for endpoint analysis, leave it off.

These traces are small (median 24 spans), so the comparison is dominated by fixed per-process cost: Python pays ~380ms/trace of interpreter + pandas startup while a Go subprocess starts in ~5ms. The speedup is therefore trace-size dependent by construction, and the corpus' own largest trace marks the other end: at 119,680 spans the identical algorithm runs 17m05s in Python vs 10m37s in Go — a 1.6× analysis-time ratio where startup is negligible. Small traces see the startup-elimination win (up to 89×), large traces see the analysis win (~1.6×), and mid-sized traces interpolate between the two. The in-memory library (ProcessSingleTraceData) removes even the spawn and the disk read.

Wins

  • Correctness: byte-parity on all 1,559,520 traces across two public research corpora — including skip-for-skip agreement and all six output files.
  • One real bug found by the corpus, fixed: multi-root / no-root traces now skip like Python instead of erroring (434e09c).
  • 277× on pathological traces: memoized drag sibling-sort (d89a742); benefits any trace whose critical path threads a wide parent. Python reference retains the original quadratic behavior.
  • Size-dependent speedup, both ends reported: 48–89× wall-clock over the Python CLI on small traces (eliminating ~380ms/trace of interpreter + pandas startup), interpolating to a 1.6× analysis-time win on the 119,680-span largest trace (17m05s → 10m37s, identical algorithm).
  • 1M-span readiness: 957k-span trace in 13s / 2.0GB, no crash — Jaeger's upper-bound guidance covered with headroom.
  • Infrastructure: resume-safe strict difftest (interrupt, rsync, continue), thread-capped workers, per-trace timeouts — reusable for every future port validation.
